# 临时请求拥有自己独立的变量，不设全局变量

变量只有两种作用域：定义在环境中的变量作用于整个 API 文档；定义在临时请求上的变量只作用于该临时请求本身，临时请求上的提取规则也只写入它自己的变量。我们刻意不提供全局变量，也不让 API 文档下的请求拥有请求级变量，从而保证任意一个请求中的 `{{name}}` 只有唯一的解析来源、无需优先级规则。代价是临时请求之间无法共享变量（例如"先登录再调用"的多步流程），这类场景应导入 API 文档并使用环境变量。

## Considered Options

- **全局变量**：所有地方可用，但引入"请求 → 环境 → 全局"的优先级链。
- **临时请求借用某个 API 文档的环境**：复用已有变量，但让临时请求与 API 文档产生隐式耦合。
- **所有请求都可定义请求级变量并覆盖环境变量**：灵活，但同名变量在不同位置解析结果不同，难以排查。
