# 按"方法 + 路径"识别接口，刷新后消失的接口直接删除其数据

刷新 API 文档时，以 HTTP 方法 + 路径（如 `GET /users/{id}`）作为接口的唯一标识，而不是 operationId；新文档中找不到对应项的接口，在用户确认后连同其当前参数与预设一并删除，不保留"失效"状态。operationId 在很多文档中缺失或由工具自动生成、不稳定，而"保留失效 + 重新绑定"会显著增加模型与界面复杂度；作为自用工具，我们接受"路径改名会丢失预设"这一代价，并通过刷新前的确认提示与刷新后的变更摘要让损失可见。

## Considered Options

- **operationId 优先，回退到方法 + 路径**：能跨路径重命名保留数据，但依赖 operationId 质量。
- **保留为失效，可重新绑定或转为自定义请求**：数据不丢，但需要额外的"失效的接口"分区与迁移流程。
