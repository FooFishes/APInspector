# APInspector — 产品需求文档（v1）

> 术语以 [GLOSSARY.md](../GLOSSARY.md) 为准；关键取舍见 [docs/adr/](./adr/)。

## 1. 定位与基础

| 项 | 决定 |
|---|---|
| 定位 | Android 上的 OpenAPI 调试工具：导入 OpenAPI 文档、浏览接口、快速请求、查看请求详情 |
| 发布 | 以 GPL-3.0 开源，通过 GitHub 分发，不上架应用商店；仅中文界面（字符串全部抽取到资源文件） |
| 存储 | 仅本地，无账号、无云同步 |
| 技术栈 | Kotlin + Jetpack Compose + **Material 3 Expressive**；网络 OkHttp；存储 Room；YAML 解析 kaml / snakeyaml-engine |
| 显示名 / 包名 | APInspector / `work.foofish.apinspector` |
| 最低版本 | Android 14（API 34） |
| 设备 | 手机 + 平板 / 折叠屏，按窗口尺寸分级自适应（见 1.2） |
| 工程取向 | 只支持 Android 14 及以上，不为旧版本兼容性妥协；全面采用当下最新的 Android 写法与最佳实践（见 [CLAUDE.md](../CLAUDE.md)） |

### 1.1 设计系统：完全使用 Material 3 Expressive

- 所有 UI 遵循 M3 Expressive，实现时使用项目内的 `material-3` skill（`.claude/skills/material-3`）作为规范参考。
- 优先使用 Compose Material3 的 Expressive 组件与 API（`MotionScheme` 弹簧动效、Expressive 按钮尺寸、形状变形、扩展圆角 token、强调字体等），按 BOM 版本启用所需的 `@ExperimentalMaterial3ExpressiveApi` opt-in。
- 主题：跟随系统亮色 / 深色；启用动态取色（Material You）；代码 / JSON 区域使用等宽字体。
- 不使用自定义设计体系或第三方 UI 组件库替代 M3 组件。
- 不做 App 锁。

### 1.2 自适应布局

按 M3 窗口尺寸分级适配，基于 Compose Material3 Adaptive（`ListDetailPaneScaffold` 等），折叠 / 展开、旋转时保持状态：

| 窗口宽度 | 典型设备 | 布局 |
|---|---|---|
| Compact（< 600dp） | 竖屏手机 | 单栏，逐页导航：首页 → 接口列表 → 接口详情 |
| Medium（600–840dp） | 折叠屏展开、竖屏小平板、手机横屏 | 双栏：接口列表 \| 接口详情 |
| Expanded（≥ 840dp） | 横屏平板 | 双栏：接口列表 \| 接口详情 |

- Medium 及以上，API 文档列表进入侧边导航（navigation rail / 抽屉），无需回到首页即可切换。
- 接口详情在各种宽度下都使用同样的三个 Tab（见 3），不做请求与响应的左右并排。
- 设置页全屏打开，不参与双栏。

## 2. API 文档

- **规范范围**：OpenAPI 3.0 / 3.1 / 3.2，JSON 与 YAML。识别到 Swagger 2.0 时明确提示"不支持"，不尝试解析。
  - 3.2 的 `query` 方法与 `additionalOperations` 中的自定义方法（如 `LINK`）作为普通接口列出。
- **首页**：平铺的 API 文档列表，支持搜索与置顶，不做分组；列表顶部固定一个"临时请求"入口（不可删除，不参与排序）。
- **导入方式**：本地文件（系统文件选择器，`.json/.yaml/.yml`）、URL 拉取、粘贴文本。
- **刷新**：URL 导入的 API 文档记住来源地址，可手动刷新；不自动定时同步。文件 / 粘贴导入的不可刷新。
  - 以"HTTP 方法 + 路径"识别同一接口（ADR-0001）。
  - 新文档中消失的接口：提示确认后，连同其当前参数、预设一并删除。
  - 刷新后展示变更摘要（新增 X / 删除 Y / 修改 Z）。
- **`$ref`**：只解析文档内部引用；外部引用（相对文件 / URL）在对应位置标记"未解析的引用：…"，不影响其余部分；必须防护循环引用。

## 3. 浏览接口

- **接口列表**：按 tag 分组（可折叠，无 tag 归入"未分组"）；每行显示按方法着色的徽章、路径、summary；`deprecated` 显示删除线；支持按路径 / summary / operationId 搜索；支持收藏接口（置顶）。
- 列表顶部为该 API 文档的"自定义请求"分区；顶栏标题下方显示当前环境，点击切换（见 5）；顶栏提供"请求记录"入口（见 7.1）。
- **接口详情**：三个 Tab，默认打开"文档"——
  - **文档**：description、参数说明、请求 / 响应 schema（可折叠树，`$ref` 可点击展开）、示例。
  - **请求**：选择环境与预设、编辑当前参数、发送；参数行只显示名称、类型与必填标记，长按查看描述。
  - **响应**：该接口最近一条请求记录的响应详情（见 7.2）；发送后自动切到此 Tab，进行中显示进度与"取消"。另有"该接口的全部记录"入口。
- 不做独立的"模型"浏览页。

## 4. 请求

### 4.1 当前参数与预设

- 每个接口自动保存一份**当前参数**（上次填写的值），可"重置为文档默认值"。
- **文档默认值**：参数依次取 `example` → `examples` 的第一个 → schema `default` → schema `examples` 的第一个 → 唯一的 enum 值，都没有则为空；Body 取 `example`，否则按 schema 生成。
- 必填参数总是发送；非必填参数与额外参数各有勾选框，不勾选则不发送但保留值。非必填参数预填文档默认值但默认不勾选。
- 文档声明的名为 `Accept`、`Content-Type`、`Authorization` 的 Header 参数按规范默认忽略：仍然显示、默认不勾选并标注；手动勾选后发送并覆盖自动值。
- **额外参数**：可为接口追加文档未声明的 Header 与 Query 参数，与声明的参数一样保存在当前参数与预设中。不支持额外的路径参数；Cookie 来自环境的 Cookie 罐。
- 参数输入按 schema：enum / boolean 用下拉；数组为可增删的值列表，对象为键值列表（`form`、`deepObject`），按 `style` / `explode` 序列化；用 `content` 描述的参数为单个文本框，原样编码。
- 每个接口可保存多个命名**预设**；加载预设 = 覆盖当前参数（有未保存改动时先确认）；支持"保存到预设"、"另存为新预设"、重命名与删除。界面显示当前参数来自哪个预设、是否已修改。
- 预设绑定接口，方法与路径不可改。
- 刷新 API 文档后，当前参数与预设按"位置 + 名称"对齐：仍存在的参数保留值与勾选；新参数取文档默认值；不再声明的 Header / Query 参数转为额外参数，路径参数丢弃；Body 保持原样，原 content type 已不存在时改为第一个新的 content type 并取文档默认值。

### 4.2 自定义请求与临时请求

- **自定义请求**：手动填写方法、URL、Header、Body，可以：
  - 归属某个 API 文档：沿用其当前环境的 baseUrl、鉴权、变量，可写相对路径；
  - 不归属任何 API 文档 = **临时请求**：写完整 URL，不继承任何配置，集中在首页"临时请求"入口。
- 临时请求可移动到某个 API 文档（单向）；与当前环境 baseUrl 相同的 URL 前缀自动改为相对路径。
- **cURL 导入**：粘贴 cURL 生成自定义请求（目标为临时请求或某 API 文档的自定义请求分区）；支持 `-X -H -d/--data-raw -F -u --compressed`，未识别参数忽略并提示；归属 API 文档时同样自动转相对路径。

### 4.3 Body

依据 `requestBody` 的 content type 生成编辑器，多个 content type 时顶部切换（`requestBody` 非必填时另有"无 Body"）；自定义请求可选同样类型：

| 类型 | 编辑器 |
|---|---|
| `application/json` | "可视化 \| 原文"切换。可视化为按 schema 引导的树：列出未填的已声明字段、增删字段与数组元素、选择值类型（含变量）、enum 下拉、`oneOf` / `anyOf` 选择变体。原文为等宽文本编辑器，按 `example` 或 schema 生成示例预填；格式化、语法检查（`{{name}}` 视为合法值；有错只提示，不阻止发送） |
| `application/x-www-form-urlencoded` | "可视化 \| 原文"切换：按 schema 引导的键值表单 ⇄ `a=1&b=2` 文本 |
| `multipart/form-data` | 键值表单，字段可为文本或本机文件；不提供原文 |
| `application/octet-stream` | 选择一个文件作为 Body |
| 其他（text/xml 等） | 纯文本编辑器 |

- 文件以系统文件选择器选取并申请持久读取授权，只保存引用（URI、文件名、大小），不复制内容；文件不可用时阻止发送。
- 自动附加 `Content-Type`（取自所选 Body 类型）、`Accept`（该接口所有响应声明的 media type，无声明时为 `*/*`）、`User-Agent`；同名的手动 Header 覆盖它们。

不做：GraphQL、gRPC。

## 5. 环境、变量、鉴权

- 每个 API 文档有多个**环境**（至少一个），同时仅一个当前环境（顶栏切换，"请求" Tab 中也可切换）。
- 导入时按 `servers` 各生成一个环境：server 变量 `{x}` 改写为 `{{x}}`，并生成同名环境变量（取其 `default`，`enum` 作为编辑时的候选值）。相对地址（含未声明 `servers` 时的 `/`）原样保留，环境标为"baseUrl 不完整"，补全前不能发送。
- 刷新 API 文档不修改、不删除、不追加环境；`servers` 有变化时在变更摘要中提示。
- 环境在"管理环境"中新建、复制、重命名、删除与编辑，编辑即时保存。
- 环境包含：baseUrl、变量、鉴权配置、跳过证书校验开关、超时覆盖、代理设置、独立的 Cookie 罐。
- **变量**以 `{{name}}` 在 URL / Header / Query / Body / 鉴权凭证中引用（ADR-0002）；变量名由字母、数字、`_`、`-`、`.` 组成，其他 `{{…}}` 按原文处理。引用的变量未定义或为空时不发送，并列出缺失的变量：
  - 环境变量作用于整个 API 文档；
  - 临时请求有自己的变量，只作用于该临时请求；
  - 不提供全局变量。
- **鉴权**（挂在环境上）：按文档的 `securitySchemes` 每个方案配置一份凭证——
  - `http bearer`：Token；`http basic`：用户名与密码；
  - `apiKey`：值；名称与位置（Header / Query / Cookie）默认取文档声明，可修改；
  - `oauth2` / `openIdConnect`：不做授权流程，可手动填 Access Token，按 Bearer 注入。
- 发送时按接口的 `security` 顺序，选第一组"所有方案都已填凭证"的选项注入；接口声明无需鉴权，或含匿名选项 `{}` 而没有可用凭证时不注入。
- **提取规则**：JSONPath → 变量，仅在 2xx 响应后执行。
  - 只能挂在接口（对其所有预设与当前参数生效）和自定义请求上；
  - 写入当前环境的变量；临时请求上的规则写入它自己的变量。
- 响应详情中长按 JSON 字段可"设为变量…"。
- 不做脚本。

## 6. 网络

- 全局允许明文 HTTP。
- **设置页**（首页顶栏进入）：默认超时、自动跟随重定向、全局代理、响应 Body 保存上限，以及响应缓存的占用与清理。
- 跳过证书校验：环境级开关，默认关闭；开启时环境标签以警示色和图标标识。
- 超时：全局默认 30 秒，环境可覆盖。
- 自动跟随重定向：默认开，可全局关闭（关闭后可见原始 3xx）。
- Cookie：每个环境独立的 Cookie 罐，持久保存（包括会话 Cookie），按 RFC 6265 匹配，自动保存 `Set-Cookie`、自动携带；可查看、删除单个与清空，不能手动新增。Cookie 位置的 API Key 与同名 Cookie 冲突时以鉴权为准。
- 发送由应用级执行器负责，离开页面不中断；同一接口同时只有一个请求在途，可取消；进程被系统杀掉时在途请求丢失。
- **代理**：支持 HTTP 与 SOCKS5（可带用户名密码）。全局默认一份；环境可选"跟随全局 / 直连 / 自定义"；临时请求跟随全局。

## 7. 请求记录与响应详情

### 7.1 请求记录

- 每次发送生成一条**请求记录**：**实际请求**（变量替换、鉴权注入后的最终 URL / 方法 / Header / Body）、发送时的当前参数、响应或网络错误（含"已取消"）、耗时与大小、来源（接口 / 预设 / 重放 / 自定义请求）、所用环境。
- 每个 API 文档（含临时请求）最多保留 500 条，超出淘汰最旧。
- 响应 Body 以文件存于缓存目录，超过保存上限（设置项，1 / 5 / 10 / 50 / 100 MB，默认 10 MB）截断：继续读完只计大小，截断后不预览图片、不能保存为文件。Body 被清理（手动或系统回收）后记录保留，Body 显示"已清理"。
- 凭证原样保存。
- 入口在接口列表顶栏：该 API 文档的记录按时间倒序，可按接口筛选、清空。
- **重放**：原样重发实际请求（不重新替换变量、不重新注入鉴权、不追加 Cookie），使用所属环境当前的网络设置（环境已删除则用全局设置），生成一条新记录。
- **恢复到当前参数**：把记录中发送时的当前参数写回该接口。

### 7.2 响应详情

| Tab | 内容 |
|---|---|
| 概览 | 状态码（2xx/4xx/5xx 着色）、总耗时及分解（DNS / 连接 / TLS / 首字节）、大小、最终 URL、环境 |
| Body | JSON 折叠树 ⇄ 格式化原文；搜索；长按复制值 / 路径 / 设为变量。图片预览；HTML / XML / 文本以文本显示；二进制显示大小与类型、可保存为文件 |
| 响应头 | 全部响应头 |
| 请求 | 实际发出的完整请求 |
| 导出 | 复制为 cURL |

不做：响应 Schema 校验。

## 8. 备份

- 手动导出 / 导入备份文件（系统文件选择器）。
- 内容：API 文档、环境（含凭证）、预设、自定义请求、提取规则、代理设置；请求记录默认不含，可勾选包含。
- 导出时可选设置密码加密，不设则明文。
- 导入仅支持"覆盖全部"。

## 9. 明确不做（v1）

Swagger 2.0；外部 `$ref`；分组 / 工作区；OAuth2 流程；脚本；全局变量；响应 Schema 校验；独立模型页；GraphQL / gRPC；自动定时同步；App 锁；多语言；备份合并导入。
